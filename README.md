# USAID Supply Chain: Delivery Performance Analysis

End-to-end analysis of 10,324 real health-commodity shipments (HIV test kits, ARVs) to 43 countries, using R, SQL, Power BI, and Python — each tool applied where it's actually the right tool, not as a checklist exercise.

**Headline finding:** the clearest observed difference in late delivery is by fulfilment route. Shipments routed through a Regional Distribution Center with no defined Incoterm were late **17.2%** of the time, vs. **5.3%** for shipments sent directly from the vendor. This is an association: route also varies with order size, product and destination.

📄 **[Read the full recommendation memo](RECOMMENDATIONS_MEMO.md)** — findings, charts, and business recommendations in one document.

## Dataset

[USAID Supply Chain Shipment Pricing Data](https://www.kaggle.com/datasets/apoorvwatsky/supply-chain-shipment-pricing-data) (SCMS Delivery History, 2006–2015). 10,324 shipments, 33 raw fields covering scheduled/actual delivery dates, shipment mode, freight cost, fulfilment route, product group, and destination country.

## What each layer does

**R (`eda.R`)** — Exploratory analysis and statistical validation: data-quality investigation (found that two cost fields mixed real numbers with categorical placeholder text), delivery-delay calculation, outlier investigation, confidence intervals on the country comparison (several "worst 15" countries turn out to be statistically indistinguishable once you account for sample size), and a time-trend analysis that surfaced a sharp, unexplained jump in late deliveries starting in 2010.

**SQL (`sql/`)** — Rebuilds the cleaned dataset in a proper relational table and re-derives every KPI independently as a validation check. This caught a real bug: `readr::write_csv()` encodes R's `NA` as the literal text `"NA"`, which SQLite's loose typing then counted as a non-null zero rather than excluding — silently deflating every freight-cost average by 30–40% until it was found and fixed with a targeted `UPDATE`.

**Power BI** — Two-page dashboard (Overview + Country deep-dive) with DAX measures, a custom flat theme, and a heatmap-style matrix visual. Building it surfaced a second real bug: the CSV export's Windows-style line endings caused Power Query to silently double every row, which inflated `Total Shipments` and diluted `% Late` until traced to the line-ending issue and fixed.

**Python (`predict_late_deliveries.py`)** — A Random Forest classifier predicting whether a shipment will be late. On the held-out 20% test split it reaches ROC-AUC 0.82 and catches 90% of late shipments, with 23% precision, at the default 0.5 cut-off. No threshold was tuned; balanced class weights are what push the model towards recall. Every step that learns from the data (country grouping, freight-cost imputation, scaling and encoding) is fitted on the training split only, inside the model pipeline. Results are saved to `model_results.csv`. Feature importance shows order size (`pack_price`, `line_item_quantity`) and fulfilment route rank above shipment mode as predictors. Importance describes what the model uses to predict, not what causes a delay.

## How to reproduce

**R:**
```r
install.packages(c("readr","dplyr","lubridate","ggplot2","janitor","skimr","tidyr"))
# then from this project's root directory:
Rscript eda.R
```

**SQL** (SQLite):
```bash
sqlite3 usaid_supply_chain.db < sql/01_create_and_load.sql
sqlite3 usaid_supply_chain.db < sql/02_sanity_check.sql
sqlite3 usaid_supply_chain.db < sql/03_clean_nulls.sql
sqlite3 usaid_supply_chain.db < sql/04_kpi_by_mode.sql
sqlite3 usaid_supply_chain.db < sql/05_late_by_country.sql
sqlite3 usaid_supply_chain.db < sql/06_country_mode_mix.sql
```

**Python:**
```bash
pip install -r requirements.txt
python predict_late_deliveries.py
```

**Power BI:** open Power BI Desktop, load `data/shipments_for_powerbi.csv`, then **View → Themes → Browse for themes** and select `powerbi/usaid_theme.json`.
